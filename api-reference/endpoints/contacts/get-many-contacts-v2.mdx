openapi: "get /v2/contacts"
description: "Searches your team's contacts with the filters of the Contacts page, and returns them sorted and paginated."
---

This is the v2 of [Get Many Contacts](/api-reference/endpoints/contacts/get-many-contacts). It
addresses the same index as the Contacts page in the app, so anything you can filter on
there, you can filter on here.

Two tiers of filtering:

- **Flat query parameters** for the common cases — `listId=clt_...`, `notInAnyCampaign=true`.
- **`advancedFilters`**, a JSON tree, for everything else, including your team's custom
  fields. [List the available fields](/api-reference/endpoints/contacts/get-contact-filters)
  to discover them.

## Filtering

The flat parameters are the v1 ones: `search`, `email`, `listId`, `notInAnyCampaign`, the
`company*` filters, `withPrimaryCompany`, `fieldRejectionReason` and `crmSyncStatus`.
`crmIds` looks contacts up by their record id in the connected CRM, and it cannot be
combined with the other filters.

### Advanced filters

`advancedFilters` takes a filter tree encoded as JSON. A node is either a **group**
(`connector` `and` / `or`, plus `children`) or a **condition** (`property`, `operator`,
`value`). The tree is bounded: **depth 5, 50 conditions**.

```json
{
  "type": "group",
  "id": "root",
  "connector": "and",
  "children": [
    {
      "type": "condition",
      "id": "c1",
      "property": "jobTitle",
      "operator": "contains",
      "value": "engineer"
    },
    {
      "type": "group",
      "id": "g1",
      "connector": "or",
      "children": [
        {
          "type": "condition",
          "id": "c2",
          "property": "company.domain",
          "operator": "ends_with",
          "value": "acme.com"
        },
        {
          "type": "condition",
          "id": "c3",
          "property": "cf_contact_tier",
          "operator": "is",
          "value": "A"
        }
      ]
    }
  ]
}
```

Every `property` must be a field returned by
[List Contact Filters](/api-reference/endpoints/contacts/get-contact-filters), and every
`operator` must be one that field's type allows. An unknown field or a wrong operator is a
`400 INVALID_FILTER` — never a silently ignored condition.

### CRM sync state

`crmSyncStatus` follows the same values as v1: `synced`, `not_synced`, `error`,
`searching`, `not_found`, or one error reason in its lowercase form
(`invalid_email`, `contact_blocked_by_company`, ...). It requires a CRM to be connected —
otherwise the request answers `400 NO_CRM_CONNECTED`.

## Sorting and pagination

`sortBy` accepts `createdAt` (default), `fullName`, `lastContactedDate` and
`company.name`; `sortOrder` is `asc` or `desc` (default `desc`). Ties are broken by the
contact id, so a page is stable across calls.

Pagination is offset-based: `limit` (default 100, max 500) and `offset` (default 0).
`limit + offset` must not exceed **10 000** — past that the request answers
`400 PAGE_WINDOW_TOO_LARGE` rather than silently serving another page.

## Coming from v1

- **No `idsOrEmails`.** v2 searches the index; it is not a lookup by id. Fetch a known
  contact with [Get Contact](/api-reference/endpoints/contacts/get-contact).
- **`crmIds` is not a lookup either.** It narrows the search, so the response keeps the
  paginated envelope and an id that matches nothing is simply left out.
- **The response is `{ data, total, limit, offset }`**, as v1's list, with the same row
  keys. Dates are ISO-8601 instants.
- **No deep pages.** v1 still serves pages past 10 000 rows, which some integrations rely
  on; v2 refuses them, so narrow with a filter instead of walking deeper.

## Examples

<CodeGroup>

```bash Contacts of one list, newest first
curl --request GET \
  --url 'https://api.lemlist.com/api/v2/contacts?listId=clt_abc123def456ghi78&limit=50' \
  --header 'Authorization: Basic <encoded-value>'
```

```bash Contacts of a company, sorted by name
curl --request GET \
  --url 'https://api.lemlist.com/api/v2/contacts?companyDomain=acme.com&sortBy=fullName&sortOrder=asc' \
  --header 'Authorization: Basic <encoded-value>'
```

```bash Advanced filter on a custom field
curl --request GET \
  --url 'https://api.lemlist.com/api/v2/contacts?limit=100' \
  --data-urlencode 'advancedFilters={"type":"group","id":"root","connector":"and","children":[{"type":"condition","id":"c1","property":"cf_contact_tier","operator":"is_any_of","value":["A","B"]}]}' \
  --get \
  --header 'Authorization: Basic <encoded-value>'
```

```bash Contacts the CRM sync refused
curl --request GET \
  --url 'https://api.lemlist.com/api/v2/contacts?crmSyncStatus=error' \
  --header 'Authorization: Basic <encoded-value>'
```

</CodeGroup>
