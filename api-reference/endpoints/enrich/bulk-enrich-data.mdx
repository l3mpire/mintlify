openapi: post /v2/enrichments/bulk
description: Performs batch enrichment for up to 500 entities to find emails, phone numbers, or LinkedIn data.
---

<Warning>
 Unlike other endpoints, this one starts with `/v2/enrichments`.
</Warning>

## How to use the endpoint

The bulk enrichment API is ideal for:
- Processing large lists of prospects efficiently
- Enriching CRM data in batches
- Finding and verifying multiple contacts simultaneously
- Automating data enrichment workflows at scale


### Required inputs

| Type | Required input | Description |
|------|---------------|-------------|
| `find_email` | `linkedinUrl` OR (`firstName` + `lastName` + (`companyName` OR `companyDomain`)) OR `email` | Find the person's email and check its deliverability |
| `find_phone` | `linkedinUrl` OR (`firstName` + `lastName` + (`companyName` OR `companyDomain`)) OR `email` | Find phone numbers |
| `verify` | a valid `email` | Verify email deliverability |
| `linkedin_enrichment` | `linkedinUrl` OR `email` OR (`firstName` + `lastName` + (`companyName` OR `companyDomain`)) | Enrich with LinkedIn profile data |

- `linkedinUrl` must be a person profile URL (`linkedin.com/in/…` or a Sales Navigator lead URL). For `find_email` and `find_phone`, any other LinkedIn URL is ignored and the other inputs must be enough on their own; for `linkedin_enrichment` it fails the row with `BAD_LINKEDIN_URL`.
- For `linkedin_enrichment`, `email` and the name combination are only used when no `linkedinUrl` is given.
- A row missing these inputs fails with `MISSING_INPUTS`; for `verify`, with `MISSING_EMAIL` when `email` is absent and `BAD_EMAIL` when it is not a valid email.
- Requesting `find_email` and `verify` in the same row runs only one of them: `verify` when `email` is a valid email, `find_email` otherwise.

Every input value must be a string, and `input` may only hold the input fields: anything else rejects the whole call with `WRONG_INPUT_FORMAT`.

### Metadata

The `metadata` field can be a string or an object whose values are strings. It is returned in the API response and in the webhooks, allowing you to track and correlate enrichment requests. Any other value rejects the whole call with `WRONG_METADATA_FORMAT`.

## Response

The API returns an array where each element corresponds to a request in the input array, in the same order. A started request returns an enrichment `id`; a request that could not be started returns an `error` code and a readable `message`.

<CodeGroup>
  ```json success
  {
    "id": "enr_ExampleA1b2C3d4E5",
    "metadata": {
      "crmId": "12345"
    }
  }
  ```

  ```json error
  {
    "error": "MISSING_INPUTS",
    "message": "Missing LinkedIn url OR the combination of first name, last name, company name, company domain",
    "metadata": "12345"
  }
  ```
</CodeGroup>

The row `error` codes are listed in [Request errors](/api-reference/objects-definitions/enrich#request-errors).

## Getting Results

<Note>
Check [Enrich Data](/api-reference/endpoints/enrich/enrich-data) for details on the enrichment result structure.
</Note>

Since enrichment is asynchronous, you can retrieve results in two ways:

1. **Webhooks (recommended)**: your team's enrichment webhooks, and the `webhookUrl` query parameter when given, receive an event for each enrichment as soon as it is over
2. **Polling**: Use the [Get Enrichment Result](/api-reference/endpoints/enrich/get-enrichment-result) endpoint with the returned enrichment ID

Learn more about webhooks in the [Enrich object definition](/api-reference/objects-definitions/enrich#webhooks).

## Request error codes

These reject the whole call with a 400 (405 for `METHOD_NOT_ALLOWED`) and a `{"error": "<CODE>"}` body. No enrichment is started.

| Error Code | Description |
|-----------|-------------|
| `WRONG_BODY_FORMAT` | The body must be a JSON array |
| `NO_ENRICHMENTS_REQUESTED` | The body must contain at least one enrichment |
| `TOO_MANY_ENRICHMENTS_REQUESTED` | Maximum 500 enrichments per request |
| `WRONG_INPUT_FORMAT` | An `input` is not an object, has a key that is not an input field, or a value that is not a string |
| `WRONG_METADATA_FORMAT` | A `metadata` is neither a string nor an object whose values are strings |
| `WRONG_ENRICHMENT_REQUEST_FORMAT` | An `enrichmentRequests` is not an array |
| `NO_WORKFLOW_REQUESTED` | An `enrichmentRequests` is empty |
| `UNAUTHORIZED_WORKFLOW_REQUESTED` | An `enrichmentRequests` holds an unknown enrichment type |
| `WRONG_WEBHOOK_URL` | The `webhookUrl` query parameter is not a valid URL |
| `METHOD_NOT_ALLOWED` | The endpoint only accepts `POST` |

## Limits

- **Maximum requests per call**: 500 enrichments
- **Rate limits**: Standard API rate limits apply (20 requests per 2 seconds)
- **Credits**: Each enrichment type consumes credits from your team's balance

See [lemlist API credits](/api-reference/objects-definitions/credits) for more information about credit consumption.
